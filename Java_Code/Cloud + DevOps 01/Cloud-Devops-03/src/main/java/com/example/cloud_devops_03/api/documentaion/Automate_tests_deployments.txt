Step 1: Understand Why We Test and Deploy

Before automation, understand the problem.

Without testing:

Bugs reach production
New features break old features

Without deployment automation:

Manual deployment mistakes
Different environments behave differently
Releases become slow
Traditional Flow
Developer
   ↓
Write Code
   ↓
Manual Test
   ↓
Manual Deploy
   ↓
Production
Automated Flow
Developer
   ↓
Push Code
   ↓
Automatic Tests
   ↓
Build Application
   ↓
Deploy Automatically
   ↓
Production

Goal:

Every code change is verified automatically.
Every successful build can be deployed automatically.
Step 2: Learn Unit Testing

Unit tests verify small pieces of code.

Example service:

@Service
public class CalculatorService {

    public int add(int a, int b) {
        return a + b;
    }
}

Test:

class CalculatorServiceTest {

    CalculatorService service =
            new CalculatorService();

    @Test
    void testAdd() {

        assertEquals(
                5,
                service.add(2,3)
        );
    }
}

Spring Boot uses:

spring-boot-starter-test

Tools:

JUnit 5
AssertJ
Mockito

Learn:

@Test
assertEquals()
assertTrue()


Step 3: Learn Mockito (Mocking)

Real services often depend on databases.

Example:

@Service
public class UserService {

    private UserRepository repo;

    public UserService(UserRepository repo) {
        this.repo = repo;
    }

    public User getUser(Long id) {
        return repo.findById(id)
                .orElseThrow();
    }
}

Instead of hitting a real database:

@Mock
UserRepository repo;

@InjectMocks
UserService service;

Mock behavior:

when(repo.findById(1L))
    .thenReturn(Optional.of(user));

Verify:

verify(repo).findById(1L);

Mockito is essential for unit testing business logic.

Step 5: API Testing

Most Spring Boot apps expose REST APIs.

Controller:

@RestController
@RequestMapping("/users")
public class UserController {
}

Test API:

@SpringBootTest
@AutoConfigureMockMvc
class UserControllerTest {

    @Autowired
    MockMvc mockMvc;

    @Test
    void getUser() throws Exception {

        mockMvc.perform(
                get("/users/1")
        )
        .andExpect(status().isOk());
    }
}

Checks:

Status codes
JSON response
Headers

This is very common in companies.

Build application:

Produces:

target/app.jar

Pipeline:

 ↓
Run Tests
 ↓
Create JAR

Maven automatically:

mvn verify

runs

Compile
Test

This is the first automation step.


Step 8: CI (Continuous Integration)

CI means:

Whenever code is pushed:

Run Tests
Build Project
Check Quality

Popular tools:

GitHub Actions
Jenkins
GitLab CI

Example GitHub Action:

name: Spring Boot CI

on:
  push:

jobs:
  build:

    runs-on: ubuntu-latest

    steps:

      - uses: actions/checkout@v4

      - uses: actions/setup-java@v4
        with:
          java-version: '21'

      - run: mvn clean test

Now every push triggers tests automatically.

Flow:

Git Push
   ↓
GitHub Action
   ↓
Run Tests
   ↓
Pass / Fail
Step 9: CD (Continuous Deployment)

After tests pass:

Build Jar
 ↓
Create Docker Image
 ↓
Deploy Server

Dockerfile:

FROM eclipse-temurin:21

COPY target/app.jar app.jar

ENTRYPOINT ["java","-jar","app.jar"]

Build image:

docker build -t myapp .

Run:

docker run -p 8080:8080 myapp

Deployment targets:

AWS
Azure
GCP
Kubernetes
VPS
